# Webhooks

Outgoing webhooks let you push Bugwatch alert data to any HTTP endpoint. Use them to integrate with incident management tools, custom dashboards, chatbots, or internal automation.

## Payload Format

When an alert rule fires and a webhook channel is attached, Bugwatch sends a `POST` request to your configured URL with a JSON payload.

**Example payload for a `new_issue` alert:**

```json
{
  "event": "alert.triggered",
  "timestamp": "2026-02-15T12:34:56Z",
  "project": {
    "id": "proj_abc123",
    "name": "web-app"
  },
  "alert_rule": {
    "id": "rule_def456",
    "name": "New fatal errors",
    "condition_type": "new_issue"
  },
  "data": {
    "issue_id": "issue_ghi789",
    "title": "TypeError: Cannot read properties of undefined",
    "level": "fatal",
    "first_seen": "2026-02-15T12:34:50Z",
    "url": "https://app.bugwatch.dev/issues/issue_ghi789"
  }
}
```

**Example payload for a `monitor_down` alert:**

```json
{
  "event": "alert.triggered",
  "timestamp": "2026-02-15T12:35:00Z",
  "project": {
    "id": "proj_abc123",
    "name": "web-app"
  },
  "alert_rule": {
    "id": "rule_xyz999",
    "name": "API monitor down",
    "condition_type": "monitor_down"
  },
  "data": {
    "monitor_id": "mon_abc111",
    "monitor_name": "Production API",
    "status": "down",
    "checked_at": "2026-02-15T12:34:55Z",
    "url": "https://app.bugwatch.dev/monitors/mon_abc111"
  }
}
```

## Headers

Every webhook request includes the following headers:

| Header | Description |
|--------|-------------|
| `Content-Type` | `application/json` |
| `User-Agent` | `Bugwatch-Webhook/1.0` |
| `X-Bugwatch-Event` | The event type (e.g., `alert.triggered`) |
| `X-Bugwatch-Delivery` | A unique ID for this delivery (UUID) |
| `X-Bugwatch-Signature` | HMAC-SHA256 signature (only present if a secret is configured) |

## Signature Verification

If you configured a `secret` on your webhook channel, Bugwatch signs every payload using HMAC-SHA256. You should verify this signature to ensure the request genuinely came from Bugwatch.

### How It Works

1. Bugwatch computes an HMAC-SHA256 hash of the raw request body using your shared secret as the key
2. The resulting hex digest is sent in the `X-Bugwatch-Signature` header, prefixed with `sha256=`
3. Your server recomputes the hash and compares it to the header value

### Verification Example (Node.js)

```js
import crypto from "crypto";

function verifyWebhookSignature(payload, signature, secret) {
  const expected = "sha256=" +
    crypto
      .createHmac("sha256", secret)
      .update(payload, "utf8")
      .digest("hex");

  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expected)
  );
}

// In your request handler:
app.post("/webhooks/bugwatch", (req, res) => {
  const signature = req.headers["x-bugwatch-signature"];
  const rawBody = req.rawBody; // ensure you capture the raw body

  if (!verifyWebhookSignature(rawBody, signature, "whsec_your_secret")) {
    return res.status(401).send("Invalid signature");
  }

  const event = req.body;
  console.log("Received alert:", event.alert_rule.name);
  res.status(200).send("OK");
});
```

### Verification Example (Python)

```python
import hmac
import hashlib

def verify_webhook_signature(payload: bytes, signature: str, secret: str) -> bool:
    expected = "sha256=" + hmac.new(
        secret.encode("utf-8"),
        payload,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature, expected)
```

## Retry Policy

Bugwatch expects your endpoint to respond with a `2xx` status code within 10 seconds. If the request fails:

- Bugwatch retries up to **3 times** with exponential backoff (5s, 30s, 120s delays)
- After all retries are exhausted, the delivery is marked as failed
- Failed deliveries are visible in the **Notification Channels** settings page

## Best Practices

- **Always verify the signature** if you have configured a secret. This prevents spoofed requests.
- **Respond quickly** with a `200 OK` and process the payload asynchronously if your handler does heavy work.
- **Use HTTPS** endpoints to protect the payload in transit.
- **Store the delivery ID** (`X-Bugwatch-Delivery`) to detect and deduplicate retried deliveries.
