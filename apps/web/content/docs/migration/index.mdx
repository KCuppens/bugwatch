# Migration Guide

Switching error tracking platforms can feel daunting, but Bugwatch is designed to make the transition straightforward. This guide explains why teams migrate to Bugwatch and provides step-by-step instructions for moving from other platforms.

## Why Migrate to Bugwatch?

### Open Source

Bugwatch is fully open source. You can inspect the code, contribute improvements, and self-host for complete data sovereignty. No vendor lock-in, no black boxes.

### Lower Cost

Bugwatch's pricing is simple and predictable. The free tier is generous enough for most small projects, and the Pro tier is priced below comparable offerings from commercial platforms.

### Simpler Setup

A single SDK package, a single API key, and you are capturing errors. No complex DSN strings, no separate performance and error SDKs, no mandatory instrumentation wrappers.

### All-in-One Platform

Error tracking, uptime monitoring, and server metrics in a single dashboard. No need to juggle multiple tools.

## General Migration Steps

Regardless of which platform you are migrating from, the process follows the same pattern:

1. **Create a Bugwatch account** and set up a project
2. **Install the Bugwatch SDK** in your application alongside your existing error tracker
3. **Run both in parallel** for a few days to verify Bugwatch is capturing errors correctly
4. **Remove the old SDK** once you are confident in the Bugwatch integration
5. **Set up alerting** to match your existing notification workflows

Running both SDKs in parallel ensures you do not lose visibility during the transition.
